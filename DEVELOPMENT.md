# Инструкция для агента-разработчика

## Цель и текущие границы

Это расширение для совместного просмотра видео YouTube. Сейчас поддерживается только YouTube; новые сайты не подключать без отдельного запроса. При добавлении поддержки другого видеосайта сначала согласовать платформу и способ идентификации ролика.

Расширение добавляет панель в YouTube, создаёт комнату по коду, синхронизирует паузу и перемотку, показывает участников, состояние буфера и общий чат. Если пользователь вводит код комнаты, открытой для другого видео, расширение автоматически переходит на видео комнаты и повторно подключается после загрузки страницы.

## Структура проекта

- `extension/manifest.json` — Manifest V3, разрешения, домены и порядок подключения скриптов.
- `extension/content.js` — панель, комнаты, чат, опрос состояния и взаимодействие с сервером.
- `extension/youtube-adapter.js` — разбор YouTube URL, поиск HTML5-плеера, чтение состояния и синхронизация плеера.
- `extension/background.js` — service worker: запросы к API и проверка GitHub Releases.
- `extension/update-checker.js` — проверка и сравнение версий GitHub Release.
- `extension/styles.css` — оформление панели поверх YouTube.
- `server/app.py` — HTTP API на Python standard library; комнаты, присутствие участников, чат и состояние воспроизведения.
- `server/tests/test_app.py` — тесты API на `unittest`.
- `tests/youtube-adapter.test.cjs` — тесты URL и поведения адаптера YouTube.
- `tests/update-checker.test.cjs` — тесты проверки релизов и сравнения версий.
- `server/Dockerfile`, `server/compose.yaml` — сборка и запуск API с SQLite в Docker volume.
- `server/nginx-watch-together.conf` — HTTPS reverse proxy для API.
- `watch-together-extension.zip` — готовый архив **только файлов расширения**, `manifest.json` должен находиться в корне архива.

## Стек и инструменты

- Chrome/Chromium Extension Manifest V3, обычные JavaScript и CSS, без сборщика и npm-пакетов.
- Python 3 и SQLite без сторонних библиотек.
- Docker Compose для API и Docker-контейнер `node:22-alpine` для тестов JavaScript.
- Nginx и Let's Encrypt на сервере.
- Git/GitHub для исходников и GitHub Releases для уведомлений об обновлении.

Среда разработки Windows может не содержать Node.js и Docker. В таком случае используйте доступный Docker-хост для проверки; не устанавливайте дополнительные зависимости в проект только ради тестов. При публикации не добавляйте SSH-ключи, токены, `.env`, базу SQLite или другие секреты.

## Поток запросов

1. `content.js` получает состояние YouTube-плеера через `youtube-adapter.js`.
2. Расширение обращается к service worker через `chrome.runtime.sendMessage`.
3. `background.js` делает запросы к `https://ext.namalkin.site/watch-together/api`.
4. API сохраняет состояние комнат в SQLite и возвращает состояние участников, воспроизведения и сообщения.
5. Service worker отдельно проверяет GitHub Releases через GitHub API; ответ GitHub не вставляется в DOM как HTML.
6. API доступен снаружи только через HTTPS Nginx. Контейнер слушает `127.0.0.1:8787`; **не открывать порт 8787 напрямую в Интернет**.

Опрос состояния комнаты выполняется раз в 1,5 секунды. Не отключайте его: он нужен для синхронизации, чата и статусов буфера.

## Проверки после изменений

Запускайте проверки из корня репозитория.

### Python API

```powershell
docker compose -f server/compose.yaml run --build --rm watch-together python -m unittest discover -s tests -v
```

### JavaScript адаптера и проверки обновлений

Если Node.js установлен:

```powershell
node --test tests/*.test.cjs
```

Если Node.js отсутствует, используйте Docker:

```powershell
docker run --rm -v "${PWD}:/work" -w /work node:22-alpine node --test tests/*.test.cjs
```

Также проверьте синтаксис всех JS-файлов (`node --check`) и корректность `extension/manifest.json`.

### Проверка собранного архива

После сборки убедитесь, что ZIP содержит непосредственно `manifest.json`, `background.js`, `content.js`, `youtube-adapter.js`, `update-checker.js`, `styles.css` и `README.txt`, а не вложенную папку `extension/`.

## Сборка и установка расширения

Собирайте ZIP только из папки `extension`:

```powershell
Compress-Archive -Path .\extension\* -DestinationPath .\watch-together-extension.zip -Force
```

Для локальной проверки откройте `chrome://extensions`, включите режим разработчика и загрузите папку `extension`. После изменения файлов нажмите перезагрузку расширения в браузере и обновите вкладку YouTube.

## Выпуск обновления расширения

Расширение проверяет endpoint `releases/latest` этого GitHub-репозитория. Проверка выполняется не чаще одного раза в 6 часов; её можно принудительно запустить кнопкой **«Проверить»** в панели. Если опубликована версия выше версии из `extension/manifest.json`, на панели и плавающей кнопке отображается уведомление со ссылкой на релиз.

Чтобы опубликовать обновление:

1. Увеличьте версию в `extension/manifest.json`.
2. Пересоберите и проверьте `watch-together-extension.zip`.
3. Создайте GitHub Release с соответствующим тегом `vX.Y.Z`.
4. Прикрепите ZIP к релизу.

GitHub Release и его тег — источник версии для уведомления. Обычный коммит в `main` сам по себе обновлением не считается. Сейчас опубликованных релизов может не быть, поэтому проверка покажет, что обновлений пока нет. Для расширений, загруженных вручную как распакованные, уведомление **не устанавливает обновление автоматически**: пользователь скачивает архив, заменяет локальные файлы и перезагружает расширение.

## Сервер и развёртывание

Локальный запуск и тесты описаны в `README.md`. На целевом хосте используется Docker Compose и bind только на `127.0.0.1:8787`; состояние базы хранится в именованном volume `watch-together-data`.

Публичный адрес проверки доступности API:

```text
https://ext.namalkin.site/watch-together/api/health
```

Корень `https://ext.namalkin.site/` может возвращать 404 — это ожидаемо: публичный хост предназначен для API, а не для сайта с главной страницей. Для диагностики проверяйте endpoint `/watch-together/api/health`.

На сервере уже работают другие сайты. Перед изменением Nginx или портов сначала изучите активную конфигурацию; меняйте только виртуальный хост `watch-together`. Перед reload обязательно выполните `nginx -t`. Не удаляйте Docker volume и не публикуйте приватные ключи/сертификаты.

После обновления серверного кода проверьте:

```bash
cd /opt/watch-together
docker compose up -d --build
docker compose ps
curl -fsS http://127.0.0.1:8787/health
```

## GitHub

Основная ветка — `main`. Перед коммитом проверьте `git status`, `git diff --check` и результаты тестов. Для push используйте авторизованный SSH или Git Credential Manager; приватный ключ не добавляйте в репозиторий. После push проверьте `git pull --ff-only` и чистое состояние рабочей копии.

## Типовые неисправности

- **Не показывается панель:** проверьте URL (`www.youtube.com` или `m.youtube.com`), разрешения manifest и перезагрузите расширение/вкладку.
- **После ввода комнаты не появилось нужное видео:** проверьте, что у участника сохранён код комнаты и YouTube открыл перенаправленный `watch?v=...` URL. Комната подключается повторно после загрузки страницы.
- **Не видны обновления:** нужен опубликованный GitHub Release с допустимой версией `vX.Y.Z`, которая больше установленной. При ошибке сети можно запустить проверку вручную.
- **API не отвечает:** сначала проверьте контейнер и локальный `/health`, затем HTTPS health endpoint; не делайте порт API публичным.
